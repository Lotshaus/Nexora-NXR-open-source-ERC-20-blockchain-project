# Contributing to Nexora

Thank you for your interest in contributing to Nexora.

Nexora is an open-source experimental Ethereum project focused on learning, development and Web3 experimentation.

## Getting Started

1. Fork the repository.
2. Clone your fork.
3. Create a new branch for your changes.
4. Make your changes.
5. Test your changes.
6. Commit your changes.
7. Open a Pull Request.

## Branches

Use descriptive branch names, for example:

```text
feature/wallet-connect
feature/web3-dashboard
fix/contract-display
docs/update-readme
```

## Pull Requests

When opening a Pull Request, please explain:

* What you changed
* Why you changed it
* How you tested it
* Whether the change affects the smart contract

Keep Pull Requests focused on a specific improvement whenever possible.

## Smart Contracts

Changes to smart contracts require additional care.

Please:

* Keep the contract simple and readable.
* Use established OpenZeppelin implementations where appropriate.
* Avoid unnecessary privileged functionality.
* Test changes before deployment.
* Clearly document important contract changes.
* Do not deploy changes to a public network without reviewing them first.

The current Nexora deployment is on the Ethereum Sepolia testnet.

## Website

For website changes:

* Keep the design consistent with Nexora branding.
* Test the website on desktop and mobile layouts.
* Make sure links and buttons work correctly.
* Avoid adding unnecessary dependencies.

## Code Style

Prefer:

* Clear and readable code
* Descriptive names
* Small, focused changes
* Useful comments where necessary
* Consistent formatting

## Issues

Before opening a new issue, check whether a similar issue already exists.

When reporting a bug, include:

* A clear description
* Steps to reproduce
* Expected behaviour
* Actual behaviour
* Relevant screenshots or logs

## Security

Please do not publicly disclose sensitive security vulnerabilities.

See [`SECURITY.md`](./SECURITY.md) for the security reporting policy.

## Code of Conduct

Please be respectful and constructive when interacting with other contributors.

Harassment, discrimination and intentionally disruptive behaviour are not welcome.
